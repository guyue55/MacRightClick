# RightClickAssistant v1.2 原生体验与可靠性升级设计

## 状态

- 日期：2026-07-10
- 决策：采用渐进式原生升级方案
- 产品定位：默认简洁、专业能力按需开启
- 目标版本：v1.2.0

## 1. 背景与真实基线

RightClickAssistant 当前是 macOS 13+ 原生应用，由 Host App 与 FinderSync Extension 组成。FinderSync 负责菜单渲染、路径监听和事件投递，Host 负责文件操作、交互面板、系统命令和 HUD。两者通过共享目录中的 UUID JSON 事件、DistributedNotification 和 kqueue 协作。

现有基础包括：

- 28 个已注册动作，默认平铺菜单，支持收藏与分类模式。
- Pending -> InFlight -> ack/reclaim 队列、异常事件隔离和冷启动消费。
- 完全磁盘访问、Finder 扩展、监听范围和动作队列诊断。
- Universal 2 App/ZIP/DMG 构建、GitHub Actions 和 Homebrew Cask。
- 68 个 XCTest 及真机压力脚本。

深度审计确认以下问题必须先于功能扩张处理：

1. XCTest 直接使用并清理真实 `~/Library/Containers/...` 共享目录。
2. 异步动作被 Runner 接管后立即 ack，Host 随后崩溃会丢失未完成动作。
3. reclaim 只比较 PID，不检查对应进程是否仍存活，权限刷新双进程阶段可能重复消费。
4. 配置锁只覆盖 save，没有覆盖完整 read-modify-write，并发设置可能互相覆盖。
5. 粘贴完成后无条件清空剪切板，可能删除用户后来产生的新剪切状态。
6. Hash 与批量图片转换同步占用 Pending 消费队列；Hash 读取错误还会被吞掉。
7. Host 与 Extension 重复维护 28 项动作注册；`associatedBundleIdentifier` 不是协议要求，导致 existential 调用落到默认 `nil`。
8. 当前 `main` 在 GitHub Swift 6.3 工具链下因 Sendable/MainActor 边界编译失败。
9. 完全磁盘访问未授权被错误归类为“右键菜单严重故障”。
10. CI 在标签构建时发布默认 `website-dev` Ad-hoc 制品，未强制 Developer ID、公证和 stapling。
11. `ContentView.swift` 超过 1800 行，页面状态、系统命令和视图渲染耦合。
12. README 的 Latest ZIP 链接不存在，截图过期且包含本机用户名路径。

## 2. 产品决策

### 2.1 采用的方案

采用“可靠性底座 -> 原生设置体验 -> 差异化动作 -> 发布闭环”的渐进升级。保留现有 FinderSync/Host 架构和用户配置格式的兼容入口，不进行一次性重写。

### 2.2 用户价值

- 用户主动打开 App 时必定看到可操作窗口。
- Finder 菜单是否可用、受保护目录是否可访问、动作是否失败分别解释。
- 新安装默认只启用少量核心动作；专业用户可主动应用专业配置。
- 异步动作只有到达成功、失败或取消终态后才从 InFlight 队列确认。
- 设置、诊断和发布状态均可验证，不再以“命令已启动”代替“业务成功”。

### 2.3 非目标

v1.2 不实现以下内容：

- Finder 已原生提供的新建文件夹、普通 ZIP、批量重命名和普通图片 Quick Action 替代品。
- 任意脚本市场、插件市场、重复文件、磁盘分析、App 卸载。
- 自定义模板、图片自定义缩放、PDF 合并；这些进入 v1.3 候选池。
- Mac App Store 沙盒迁移。
- 全量 Xcode 工程重写或第三方更新框架。
- 在缺少 Developer ID 和公证凭据时继续自动发布“正式版”。

## 3. 完成标准

v1.2 只有同时满足以下条件才算完成：

1. 所有自动测试只读写临时目录，不触碰真实用户配置和队列。
2. GitHub `main` 单元测试、脚本检查、Cask 检查和 Universal 2 构建全部通过。
3. Host/Extension 只从一个默认动作注册入口获得动作集合，ID 唯一。
4. 所有异步动作 completion 恰好调用一次，InFlight 在终态前不删除。
5. 活跃 PID 的 InFlight 目录不会被其他 Host reclaim。
6. `paste A -> cut B -> A 完成` 后 B 仍保留；部分失败时失败项可再次粘贴。
7. 完全磁盘访问未授权不会把“菜单可用”误报为严重故障。
8. 动作页支持搜索、类别/状态筛选、精简配置、专业配置和自定义状态。
9. 新增 Shell 安全路径与 Git 相对路径两个差异化动作，并有纯逻辑单元测试。
10. 用户点击“检查更新”才发起网络请求；不后台轮询、不上传数据。
11. 标签发布必须验证 tag、VERSION、包版本一致，并使用签名公证路线。
12. README/README_EN/CHANGELOG、功能数、下载链接和真实截图一致。

## 4. 产品模式与配置迁移

### 4.1 动作层级

新增 `ActionTier`：

- `essential`：精简配置中的核心动作。
- `professional`：开发、文档、媒体和外部工具动作。
- `advanced`：永久删除、移动到、复制到、切换隐藏文件等高风险动作。

`MenuAction` 必须声明 `tier` 和 `associatedBundleIdentifier`。后者允许 Extension 预热应用安装状态，并让设置页正确显示“未检测到应用”。

### 4.2 动作配置

新增 `ActionProfile`：

- `essential`：新建 TXT、剪切、粘贴、拷贝文件名；菜单模式为 flat。
- `professional`：启用所有非高风险内置动作；菜单模式为 grouped，避免一级菜单膨胀。
- `custom`：用户逐项调整后的状态。

应用 profile 是用户显式命令，必须先确认。收藏顺序不变，高风险动作不被批量开启或关闭。

### 4.3 旧用户迁移

新增 `settings_schema_version = 2`：

- 若迁移前 `config.json` 已存在，先按照旧版默认值和现有显式覆盖物化全部 28 个动作状态，再标记为 `custom`。
- 若迁移前没有配置文件，应用 `essential` 作为新安装默认配置。
- 迁移在 Host 注册动作后执行一次，通过单个配置事务写入，完成后发送一次配置变更通知。
- Extension 在 Host 迁移前仍能按旧默认值渲染；收到通知后刷新缓存。

## 5. 架构设计

### 5.1 默认动作注册

新增 `DefaultActionRegistry`：

```swift
public enum DefaultActionRegistry {
    public static func makeActions() -> [MenuAction]
    public static func registerAll(into dispatcher: ActionDispatcher)
}
```

Host 与 Extension 均调用 `registerAll`。注册表保持确定顺序，并在测试中校验动作 ID 唯一和总数 30。Extension 暂时继续链接动作实现，以避免本版本同时重写描述符/执行器边界；拆成纯 `ActionDescriptor` 属于后续架构工作。

### 5.2 版本化动作上下文

新增：

```swift
public enum ActionInvocationKind: String, Codable, Sendable {
    case items
    case container
}
```

`SharedActionEvent` 增加 `schemaVersion` 与 `invocationKind`。自定义 Codable 解码让旧事件默认使用 schema 1 和 `.items`。FinderSync enqueue 时写入真实菜单来源，Host Dispatcher 使用同一上下文重新执行 `isAvailable` 校验。

### 5.3 异步终态与队列确认

新增协议要求：

```swift
public enum ActionCompletionStatus: Equatable, Sendable {
    case succeeded
    case failed
    case cancelled
}

public enum ActionSubmission: Equatable, Sendable {
    case accepted
    case rejected
}

func submit(
    targetURLs: [URL],
    completion: @escaping @Sendable (ActionCompletionStatus) -> Void
) -> ActionSubmission
```

默认实现包装现有同步 `execute`。异步动作覆盖 `submit`，在真实 IO/交互终态调用 completion。Host 行为固定为：

- `accepted`：保留 lease，completion 到达后 ack。
- `rejected`：记录原因并 ack，避免 poison event 无限重放。
- Host 在 completion 前崩溃：lease 留在 InFlight，下一次安全 reclaim。
- completion 必须恰好调用一次；Runner 和 Coordinator 测试覆盖重复回调防护。

### 5.4 存储与测试隔离

`SharedStorageManager` 接受可注入的共享根目录，同时保持 `shared` 生产实例：

```swift
public init(sharedContainerURLOverride: URL? = nil)
```

配置 read-modify-write 由同一个串行临界区完成，新增批量接口：

```swift
public func setActionEnabledStates(_ states: [String: Bool])
public func clearFailedActions() throws
```

所有存储测试创建独立临时目录，并断言该路径不位于 `~/Library/Containers`。Package target 显式排除 shell 测试文件。

### 5.5 InFlight 所有权

本版本保留 PID 目录格式，但 reclaim 前通过 `kill(pid, 0)` 判断进程是否存活：

- 当前 PID 或仍存活 PID：跳过。
- `ESRCH`：允许 reclaim。
- `EPERM`：视为进程存在并跳过。
- 非数字目录：隔离或忽略，不作为 PID 处理。

后续版本可升级为 UUID owner + heartbeat lease；v1.2 不同时更改磁盘目录协议。

### 5.6 剪切板一致性

`clipboard.json` 升级为带 UUID 的 `CutClipboardSnapshot`，兼容旧 `[String]` 解码。粘贴捕获 snapshot ID，完成后仅在当前 ID 未变化时清理或更新失败项。若用户期间产生新剪切状态，不修改新 snapshot。

### 5.7 后台执行与系统命令

- Hash 和图片格式转换提交到专用 `BackgroundActionRunner`，不占用 Pending 消费队列。
- `FileHashCalculator` 不再吞掉读取错误。
- 删除确认与其他交互动作共用 `InteractiveActionGate`。
- `SystemCommandRunner` 统一 timeout、退出码、stdout/stderr 和 terminate/kill 逻辑；`SystemReloader` 与切换隐藏文件均复用。
- 后台常驻不再永久请求 `idleSystemSleepDisabled`；依赖 kqueue 和系统事件唤醒。
- 权限刷新 relaunch 同时传入 `permissionRefreshArgument`，确保新进程执行 Finder 刷新逻辑。

### 5.8 执行端防御

Host Dispatcher 在执行前重新检查：

1. action ID 已注册。
2. action 当前仍启用。
3. 事件上下文仍满足 `isAvailable`。
4. 目标路径仍存在，免路径动作除外。
5. 外部应用依赖仍可用。

菜单隐藏不是安全边界；高风险动作仍必须在 Host 端逐次确认。

## 6. 健康诊断设计

### 6.1 状态分层

健康状态拆成三条，不再混成一个“已授权/未授权”：

- 菜单服务：Finder 扩展注册、启用、最近心跳、实际监听数量。
- 文件访问：完全磁盘访问，明确标为“可选；仅影响受保护目录”。
- 动作队列：Pending 数量、最老事件年龄、Failed 数量。

严重程度：

- 扩展未注册/未启用，或最近心跳缺失且菜单不可验证：critical。
- FDA 未授权、Failed > 0、Finder 可能使用旧会话：warning。
- 扩展近期心跳正常、实际监听数量 > 0、队列无失败：healthy。

### 6.2 Extension 心跳

Extension 在初始化、配置刷新以及菜单触发时按最多每 60 秒一次写入 heartbeat：时间、PID、版本、实际 `directoryURLs.count`。Host 只展示心跳元数据，不展示完整监听路径。

### 6.3 诊断动作

诊断页固定提供：

- 推荐修复动作（只突出一个）。
- 重新检测。
- 一键注册扩展。
- 重启 Finder。
- 重新打开并重启 Finder。
- 打开扩展设置。
- 清理失败记录。
- 复制无路径、无隐私数据的诊断摘要。
- 打开 Console 与复制 OSLog 查询命令。

## 7. 设置界面设计

### 7.1 信息架构

设置窗口保留五个页面，但改为用户任务命名：

1. 通用：服务就绪、登录启动、静默启动、成功提示、版本与检查更新。
2. 动作：配置 profile、菜单模式、搜索、类别/状态筛选、启用与收藏。
3. Finder：扩展状态、监听范围、云盘兼容、自定义目录、可选 FDA。
4. 诊断：独立检查项、最近失败、推荐修复和日志工具。
5. 高级：高风险动作、外部工具、恢复设置。

### 7.2 文件拆分

- `ContentView.swift`：根 `NavigationSplitView` 与路由，不承载页面业务。
- `GeneralSettingsView.swift`
- `ActionsSettingsView.swift`
- `FinderSettingsView.swift`
- `DiagnosticsSettingsView.swift`
- `AdvancedSettingsView.swift`
- `SettingsComponents.swift`

页面系统状态读取与命令调用放入各自 ViewModel/服务；视图只负责绑定和呈现。单文件目标控制在约 500 行以内，根视图控制在约 250 行以内。

### 7.3 视觉与交互准则

- 使用系统 Form、Section、Label、Picker、Toggle、Menu 和 Button。
- 去掉营销式“免费开源”胶囊、超大页面标题、渐变状态卡和持续脉冲动画。
- 颜色只辅助表达，状态必须同时有图标和文本。
- 操作按钮按推荐动作排序，不同时突出多个主按钮。
- 动作收藏按钮和 Toggle 添加包含动作名称的 accessibility label/value。
- 动画尊重 Reduce Motion；深色模式使用语义色。
- 设置快捷键使用标准 `Command-,`。
- “恢复全部设置”必须确认；恢复后提供明确结果，不使用即时无确认清空。

## 8. v1.2 新功能

### 8.1 Shell 安全路径

- 动作 ID：`guyue.action.utility.copyShellPath`
- 多选时将每个 POSIX 路径用单引号安全转义，并以空格连接，可直接作为 shell 参数粘贴。
- 单引号按 POSIX 规则转换为 `'\''`。
- 仅处理选中项；默认属于 professional。

### 8.2 Git 相对路径

- 动作 ID：`guyue.action.utility.copyGitRelativePath`
- 从每个目标向上查找 `.git` 文件或目录。
- 所有目标均位于 Git 工作树内时显示；跨仓库多选允许，每行输出一个相对路径。
- 仓库根目录输出 `.`；符号链接按 standardized URL 处理，不主动解析到仓库外。
- 默认属于 professional。

### 8.3 显式检查更新

- 用户点击后请求 GitHub Releases `latest` API。
- 解析语义版本；新版本可用时提供“查看发布页”。
- 当前已是最新、网络失败、响应无效分别展示明确结果。
- 不自动下载、不自动替换 App、不在后台定时检查、不上传设备信息。

## 9. 发布与供应链

### 9.1 CI 分层

- `unit`：SwiftPM 测试。
- `scripts`：`bash -n`、Python `py_compile`、文档硬编码扫描。
- `cask`：Cask 结构、Ruby syntax、临时 tap 下 brew style/audit。
- `build-smoke`：website-dev Universal 2 构建及产物结构验证，只读权限。
- `release`：仅 tag，使用 `contents: write` 和受保护 Environment。

### 9.2 正式发布门禁

tag 发布必须：

1. 验证 `refs/tags/vX.Y.Z == VERSION == CFBundleShortVersionString`。
2. 导入 Developer ID 证书。
3. 显式 `DISTRIBUTION_ROUTE=website-release`。
4. 对 App 与 DMG 公证并 staple，随后执行 `codesign`、`spctl`、`stapler validate`、`hdiutil verify`。
5. 生成版本化 DMG/ZIP、Latest DMG/ZIP、SHA256SUMS 和非空 Release notes。
6. 缺少签名或公证凭据时 release job 失败，不回退为 Ad-hoc 正式发布。

### 9.3 Homebrew

Cask 从可变 Latest URL 改为不可变版本 URL和真实 SHA-256，并增加 `livecheck`。v1.2 发布前 Cask 可继续指向已存在的 v1.1.1 制品；v1.2 正式签名制品生成后再更新版本与哈希。长期迁移到 `homebrew-macrightclick` 独立 tap。

## 10. 文档与隐私

- README 只描述已发布稳定版；未发布能力放在 CHANGELOG `Unreleased`。
- 修复 `~/Library/Containers` 架构路径、Latest ZIP、错误转义的 `$(pwd)` 和 Homebrew 更新说明。
- “28 个动作”改为由注册表测试与文档脚本共同校验；新增两个动作后稳定版文档写 30 个。
- ActionVerifier 文案改为“验证 10 项关键链路”，不再声称验证全部动作。
- 新截图使用专用测试账户或对路径脱敏，同时覆盖浅色、深色和 Finder 菜单。
- OSLog 默认把路径视为 private；诊断摘要不复制用户路径。

## 11. 测试策略

### 11.1 单元测试

- `DefaultActionRegistry`：30 个唯一 ID、层级、高风险默认策略。
- `SharedStorageManager`：临时根目录、配置并发更新、批量 profile、Failed 清理。
- 队列：活 PID 不 reclaim、死 PID reclaim、legacy event 解码、异步 completion 后 ack。
- 剪切板：compare-and-clear、部分失败保留、新剪切不被旧 paste 清理。
- Dispatcher：禁用动作、错误上下文、缺失路径、外部依赖均拒绝。
- Hash：读取错误向上传播，后台任务不阻塞快速动作提交。
- Modal：删除、移动、隐藏文件共用一个 gate。
- PathCopyService：空格、单引号、Unicode、多选、Git 根/子目录/跨仓库/仓库外。
- UpdateChecker：版本比较、API 解码、网络/HTTP/无效数据错误。
- Diagnostics：FDA warning、扩展 critical、heartbeat 过期、Failed warning。

### 11.2 构建与静态验证

- `git diff --check`
- `swift test`
- `bash Tests/CaskStructureTests.sh`
- `bash -n Scripts/*.sh`
- `python3 -m py_compile Scripts/stress/*.py`
- `./Scripts/build.sh`
- `lipo -info`、`codesign --verify --deep --strict`、`hdiutil verify`

本机若仍因 Command Line Tools 的 PackageDescription ABI 错误无法启动 SwiftPM，必须记录为环境阻塞；GitHub 固定工具链测试仍必须通过，不能用本地 build 代替单元测试结论。

### 11.3 真机验收

- 主动打开、登录项启动、Finder 后台拉起、权限刷新四种启动来源。
- Finder 空白、文件、文件夹、多选、外接盘、iCloud/CloudStorage 路径。
- FDA 未授权时菜单正常但受保护目录提示受限。
- 快速连续提交、Host 中途退出、双 Host relaunch、粘贴期间再次剪切。
- VoiceOver 动作行朗读、全键盘操作、Reduce Motion、深色模式。
- Homebrew 安装/升级/卸载和扩展注销。

## 12. 实施阶段

### 阶段 A：发布阻断与数据安全

测试存储隔离、Swift 6.3 编译、权限刷新参数、空闲睡眠、配置事务、活 PID reclaim、粘贴 snapshot、Hash 错误传播。

### 阶段 B：动作契约与执行稳定性

统一注册表、动作层级、事件 v2、执行端复核、异步终态 ack、全局 modal gate、后台化重任务。
