# File Provider 统一服务动作面板

## 目标

在 iCloud Drive、CloudStorage 等 Finder 可能抑制 FinderSync 菜单的目录中，把原有 5 个分散的系统服务收敛为一个“右键助手…”入口。用户打开后看到当前选中项真正可执行的动作，再由现有共享事务队列提交执行。

## 核心设计

1. `FinderServiceCatalog` 是服务入口与动作可见性的唯一纯逻辑边界：
   - Info.plist 只注册一个稳定的 `NSUserData`。
   - 从 `DefaultActionRegistry` 注册的动作中筛选已启用、当前上下文可用的动作。
   - 收藏优先，其余按既有分类与中文名称排序。
   - 输出不可变展示模型，UI 不读取权限配置，也不硬编码动作 ID。
2. `FinderServicesProvider` 只负责解析 Finder pasteboard、请求展示面板，以及在用户选择后再次校验并入队。
3. `FinderServicePaletteController` 持有唯一轻量 `NSPanel`；再次调用时替换上下文，避免重复窗口和生命周期泄漏。
4. SwiftUI 面板只渲染后端提供的动作列表，并提供本地搜索。动作总量固定为 30，搜索与排序均为内存操作。
5. 最终执行仍经过 `SharedStorageManager.enqueueAction` 和 Host 的 `ActionDispatcher`，保留目标存在性、动作可用性、高风险确认与失败回收机制。

## 权限与安全边界

- 不申请辅助功能、自动化或新的隐私权限，不使用私有 API。
- 前端不决定动作是否可见或可执行；动作开关、外部应用可用性和上下文适用性均由核心层计算。
- 点击动作时再次校验，防止面板打开后配置或文件状态变化造成越权或错误执行。
- 高风险动作只有在用户已于设置中主动启用且当前可用时才出现，原有动作确认流程保持不变。

## 性能与非目标

- 仅在用户调用系统服务时解析动作，不新增轮询、常驻任务、网络请求或 shell 命令。
- 不复制设置页组件，不新增动作配置存储，不改变普通目录的 FinderSync 一级菜单。
- 不硬编码全局快捷键，避免与用户现有快捷键冲突；用户可在 macOS“键盘快捷键 > 服务”中自行设置。
- 系统服务只接收 Finder 已选中的文件或文件夹，不伪造空白背景上下文。

## 执行与验收

1. 先补充纯逻辑测试：单入口常量、启用/可用过滤、收藏排序、搜索、路径规范化。
2. 实现纯逻辑解析器，再实现单例面板与二次校验入队。
3. 构建脚本将 `NSServices` 收敛为一个声明，并校验产物 Info.plist。
4. 更新中英文 README、权限页和诊断页说明。
5. 运行 `swift test`、结构测试、`git diff --check`、`./Scripts/build.sh`、签名与产物检查。
6. 安装本地构建后，在 Downloads 与 File Provider 目录验证入口、搜索、禁用动作隐藏、执行入队和重复打开窗口行为。
