# Finder 服务快捷动作设计

## 目标

当 FinderSync 在 iCloud Drive、CloudStorage 等 File Provider 目录中不显示时，用户仍能在“服务”中直接使用收藏和常用动作；稳定入口“右键助手…”始终保留，并打开带分类的完整动作面板。

## 交互结构

- “服务”直达项：收藏优先，推荐常用补齐，去重后最多 8 项。
- “右键助手…”：完整入口，面板提供“全部、常用、新建、文件、终端、工具”分类和搜索。
- “全部”：收藏、推荐常用、其余分类依次展示，同一动作只出现一次。
- “常用”：收藏与推荐常用的并集，收藏顺序优先。

推荐常用动作固定为：剪切、拷贝完整路径、拷贝文件名、在系统终端中打开、获取 SHA256。推荐表和排序只存在于核心策略，不在 UI、服务清单和脚本中重复维护。

## 架构边界

1. `FinderQuickActionPolicy` 是纯逻辑模块，统一处理收藏顺序、推荐补齐、去重、安全过滤和数量上限。
2. `FinderQuickServiceManager` 仅编入 Host，根据策略生成标准 `.service` bundle，并原子更新 `~/Library/Services` 中的清单和 helper。
3. `.service` 内的 Universal helper 只把动作 ID 通过私有 pasteboard 类型转发给静态“右键助手…”服务，不读取配置、不执行动作，也不复制动作引擎。
4. 配置变化采用事件驱动和防抖刷新；内容未变化时不写磁盘、不刷新系统服务，无后台轮询。
5. `FinderServicesProvider` 不信任转发的动作 ID。执行前重新计算当前直达集合，并复用现有目标可用性校验和动作队列。
6. SwiftUI 面板只渲染核心层产生的分区模型，不自行判断开关、外部应用或动作权限。
7. 动态服务创建或转发失败不影响静态“右键助手…”入口，卸载时清理动态服务并刷新系统缓存。

## 安全与性能

- 高风险动作即使被收藏也不进入直达服务，只能从完整面板执行。
- 依赖外部应用的动作仅在应用已安装时进入动态服务；点击时再次校验。
- 启动和配置变化仅线性扫描当前已注册动作一次，直达输出固定最多 8 项。
- 服务清单和 helper 只在内容或执行权限变化时原子更新，刷新防抖 300 毫秒。
- 服务标题使用 `1...8` 编码稳定顺序，收藏项附加 `★`；不使用不可见字符或私有菜单 API。

## 验收标准

- 收藏按存储顺序位于推荐动作之前，重复项只显示一次，总数不超过 8。
- 禁用、高风险、依赖未安装应用的动作不进入直达服务。
- 伪造或过期的动作 ID 无法绕过服务提供者校验。
- “右键助手…”面板保留完整分类、搜索与执行前二次校验。
- 启动、收藏/开关变更后服务清单可刷新；无变化不产生写入。
- 本地卸载脚本以及 Homebrew 普通卸载、`zap` 都能清理动态服务。
